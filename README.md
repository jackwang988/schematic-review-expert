# 原理图辅助评审 Skill

**让 AI 沿着“图纸 → 连线 → 手册 → 证据”的路径，帮你把原理图检查得更有章法。**

面向硬件工程师、嵌入式开发者和电子爱好者。提供原理图 PDF、对应器件手册，以及可选的设计 checklist，让支持 Skills 的 AI 助手按六阶段流程辅助评审，输出可回到图纸逐项核对的报告。

作者：[Jack](https://github.com/jackwang988) · 公开版 `2.2.1-public` · [MIT](LICENSE) · [下载 ZIP](https://github.com/jackwang988/schematic-review-expert/archive/refs/heads/main.zip)

> **先看适不适合你：**你希望在设计自查、同事评审前或改版复核时，多一份结构化检查清单，并知道每条疑点的依据在哪里。本项目提供工作流与工具，完整评审需要 AI 助手参与；关键结论仍需工程师复核。

## 你可能遇到过这些情况

- 一张多页原理图，电源和跨页网络来回跳，检查时容易漏掉一段连接。
- 手册很长，知道要看电源、复位和启动配置，却还没整理出逐项可核对的要求。
- AI 看图后直接说“这里缺少上拉”，但没有追完整条网络，也没核实芯片内部是否已有偏置。
- 评审意见写成“建议优化”，没有位号、页码、规则依据，后续难以整改和复查。

这个 Skill 把上述工作拆成明确步骤：先整理图纸事实，再查适用规则，最后区分**已证实问题、待确认项与未覆盖范围**。

## 完整工作流：六个阶段

下面是一次评审从输入到报告的完整路径。每阶段都要求保留输出，让后续判断有据可查。

| 阶段 | 具体做什么 | 留下什么 |
|---|---|---|
| **0 · 资料确认与预处理** | 确认版本、页数和评审重点；区分文本/扫描页面；检查手册、规范是否齐全 | 页面信息、提取文本或图片、资料缺口清单 |
| **1 · 建立网络与器件名录** | 整理位号、型号、封装标注、电源域与跨页标签；区分交叉线与连接点 | 器件名录、关键网络及跨页追踪入口 |
| **2 · 确认器件与依据** | 对照具体型号、封装和版本的原厂手册，核实电源、引脚、默认状态及外围要求 | 规则依据、版本/章节、需要补充的器件资料 |
| **3 · 逐连接检查** | 从目标引脚沿线追踪，再反向核对；检查电源、复位、启动、时钟及接口 | 带位号、网络、页码和坐标的检查记录 |
| **4 · 匹配自有规范** | 有 checklist 时按模块或关键词加载实际条款；没有则标注未覆盖 | 有明确条款号的不符合项，或规范缺失说明 |
| **5 · 交叉复核与报告** | 检查识别与推理是否闭环，排除型号、单位和连线误读；分级整理结果 | 已证实问题、待确认项、覆盖矩阵与整改建议 |

详细规则见 [六阶段工作流](references/review-workflow.md)。

### 哪些检查点值得重点看

| 模块 | 检查方向 |
|---|---|
| 电源 | 各电源域的来源、推荐工作范围、去耦、使能与时序 |
| 复位与启动 | 引脚极性、内部/外部偏置、启动采样状态及复位要求 |
| 时钟 | 时钟源频率、供电、晶体负载条件与必要外围 |
| 数字接口 | 信号方向、电平域、开漏偏置、连接器与保护器件 |
| 跨页连接 | 同名网络、端口、跳线和未装元件是否造成理解歧义 |
| 密集标签 | 位号与数值是否配错；局部截图是否遗漏了其他连接 |

具体要求由对应器件及适用规范决定，不把通用经验直接套到所有芯片。

### 它如何约束 AI 的判断

1. **先确认型号与引脚定义。**相似型号、不同后缀和不同封装不能直接互用。
2. **先追踪，再判缺件。**“附近没看到电阻”不足以证明缺少上拉。
3. **结论要有两端证据。**一端是图纸连接事实，另一端是适用的手册或规则。
4. **资料不足就写待确认。**识别存疑、手册缺失、连接未闭环，不计为已证实错误。
5. **把覆盖范围写出来。**没查的模块和无法完成的检查，不用“通过”一笔带过。

这些是工作流约束，不能保证模型每次都正确执行，仍需检查报告中的证据。

## 三个使用案例

以下为可直接改写的任务示例，不是已经完成的实测案例，也不代表检出率。

### 案例一：设计完成后，先检查电源与复位

**准备：**原理图 PDF，以及目标芯片对应封装、版本的原厂手册。

```text
用 $schematic-review-expert 评审 uploads/demo.pdf。
重点看电源、复位和启动配置。
先列出资料缺口，再逐引脚核对并追踪跨页网络。
每条疑点附位号、页码、坐标和手册依据；拿不准的列待确认。
报告保存到 output/。
```

**你应检查的输出：**它是否先确认芯片身份；电源域是否逐个核对；复位意见是否有手册支持；跨页连接是否有完整路径。

### 案例二：把自己的 checklist 变成可查询规则

**准备：**有权处理且符合 [导入表结构](GUIDE.md#excel-导入表结构) 的 checklist.xlsx。

```bash
python scripts/build_company_rules.py "uploads/checklist.xlsx"
python scripts/kb_search.py --list-modules
python scripts/kb_search.py --keyword 复位 去耦
```

再告诉 AI：

```text
用 $schematic-review-expert 检查 uploads/demo.pdf。
先核实公司规则索引实际有多少条，再匹配本次涉及的模块。
发现不符合项时引用真实条款号；没有适用条款就说明原因。
原厂要求与 checklist 冲突时单独列出，不要直接给出合规结论。
```

**你应检查的输出：**规则是否成功导入，引用的条款是否真实存在，是否把 PCB 布局条款错误当成原理图检查结论。

### 案例三：扫描图或标签密集，看不清就先复核

**准备：**扫描 PDF、清晰局部图或能提供时的原始网表。

```text
用 $schematic-review-expert 检查 uploads/scanned-demo.pdf。
先判断哪些页面需要图像识别，列出看不清的型号、引脚和连接。
标签密集处不要只按最近距离配对；追不通的网络标为待确认。
先输出识别复核清单，再检查有充分证据的部分。
```

**你应检查的输出：**它有没有区分识别问题和设计问题，有没有明确提出需要哪张局部图或哪份资料，而不是把模糊图强行判成错误。

## 报告会长什么样

下面是一段**虚构教学样例**。U_DEMO、V_DEMO、数值、页码及坐标全部为示意，不能作为任何实际器件的设计要求。仓库未附带该示例原理图或手册。

| 项目 | 样例内容 |
|---|---|
| 检查对象 | U_DEMO 的电源引脚 |
| 图纸事实 | 示例第 2 页、区域 `(120,80)–(180,140)`，目标引脚接到 V_DEMO 网络 |
| 示例已知条件 | 假定来源资料明确该网络为 5.0 V，且引脚没有其他供电路径 |
| 示例规则 | 假定用户提供的虚构手册 §4.2 规定推荐工作范围为 2.7–3.6 V |
| 判定 | 在上述假设均经核实的前提下，连接超出推荐工作范围 |
| 建议 | 按实际原厂要求重新核对供电方案，修改后复查 |

如果缺少“5.0 V 的可靠来源”或“对应手册 §4.2”，同一个问题就应进入**待确认项**，不能仅凭网络名或参考卡判错。

一份完整报告还应包含：

- **概览：**输入版本、页面范围、已有资料和缺失资料。
- **问题明细：**等级、位号/网络、页码/坐标、事实、依据和建议。
- **待确认项：**无法确认什么，缺少哪份资料，下一步如何补证据。
- **覆盖矩阵：**哪些模块已检查、部分检查或未检查，以及原因。
- **限制：**是否缺少网表、PCB、仿真或硬件实测；未发现问题不等于完整通过。

## 安装到 Codex


需要 Git、Python 3.10+ 和支持本地 Skills、文件读取与脚本执行的 Codex。克隆到用户技能目录下；如目录已存在，请先备份，不要覆盖用户知识库。

macOS / Linux：
```bash
mkdir -p ~/.agents/skills
git clone https://github.com/jackwang988/schematic-review-expert.git ~/.agents/skills/schematic-review-expert
cd ~/.agents/skills/schematic-review-expert
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/kb_search.py --list-chips
```

Windows PowerShell：
```powershell
New-Item -ItemType Directory -Force "$HOME/.agents/skills" | Out-Null
git clone https://github.com/jackwang988/schematic-review-expert.git "$HOME/.agents/skills/schematic-review-expert"
Set-Location "$HOME/.agents/skills/schematic-review-expert"
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts/kb_search.py --list-chips
```

重新开启 Codex 会话，并在提示词中告知虚拟环境 Python 的路径。安装目录依据 [官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)；其他宿主请按其本地 Skill 目录安装，并完整保留目录结构。本仓库公开不等于自动安装到 ChatGPT Work。

## 第一次使用：从一份自己的 PDF 开始

1. 按上面的命令完成安装，确认依赖可以导入。
2. 将可处理的原理图 PDF 放到 `uploads/`，同时准备目标芯片的原厂手册。
3. 如需先入库，执行下面命令；生成后请让 AI 对照手册核实卡片内容。
4. 使用前面的案例提示词发起评审，明确本次重点与资料范围。
5. 到 `output/` 查看报告，逐条回到原理图核对证据。

```bash
# 初始芯片库为空是正常现象
python scripts/kb_search.py --list-chips

# 用自己的原厂手册建立本地规则卡骨架
python scripts/ingest_datasheet.py "uploads/chip.pdf" "YOUR-CHIP"

# 预处理自己的原理图
python scripts/extract_schematic.py "uploads/demo.pdf"

# 运行仓库的合成数据测试
python -m unittest discover -s tests -v
```

上面的 `demo.pdf`、`chip.pdf` 和 `YOUR-CHIP` 都是占位符，请替换为自己的文件和型号。入库脚本生成骨架，完整评审由 AI 助手按工作流执行；单独运行预处理脚本不会自动生成完整评审报告。

## 哪些能做，哪些需要其他工具

| 任务 | 本项目的角色 |
|---|---|
| PDF 内容提取、位号与电源网络提示 | 由脚本辅助完成，需关注扫描图识别限制 |
| 对照手册、追踪连接、整理评审意见 | 由 AI 按流程辅助执行，关键结论由工程师复核 |
| 公司规则匹配 | 需先导入用户自有 checklist，公开版未内置 |
| 网表/ERC、PCB 规则检查 | 需要 EDA 工具，本项目不能替代 |
| 高速信号、射频、热与时序验证 | 需要相应模型、仿真工具及设计资料 |
| 实际电压、波形、启动和可靠性 | 需要硬件实测，不能凭 PDF 证明 |

目前提供脚本的合成数据测试，未发布真实原理图准确率、检出率、节省时间或与人工评审的对比数据。案例提示词和虚构报告样例用于说明使用方法，不构成效果实测。

## 常见问题

**没有公司 checklist，能用吗？**  
可以进行有充分器件资料支持的检查。报告会说明公司规范维度未覆盖。

**为什么没有内置芯片规则卡？**  
公开版移除了原始项目知识库和厂商原文，避免带出项目资料。使用者从自己有权处理的手册开始建库，核对后在本地复用。

**只有扫描 PDF，可以用吗？**  
可以先预处理并交给具备图像读取能力的 AI；效果取决于清晰度和工具能力。连接无法确认时，需要局部高清图、原始 EDA 或网表补充证据。

**会自动把原理图传到 GitHub 吗？**  
脚本没有自动提交或遥测上传逻辑。`.gitignore` 默认忽略用户图纸、手册、规则卡和报告；已跟踪文件仍需人工检查。使用云端 AI 时，资料处理方式由平台和用户设置决定，不能据此宣称全程离线。

**其他 AI 工具能安装吗？**  
可以按其本地 Skills 规范放置完整目录，并确保能读取文件、图像及执行 Python。仓库没有承诺所有宿主均已测试兼容。
